阅读时长: 2 分钟

分析

下面是移除了注释后的类型文件 ~/.local/share/nvim/mason/packages/lua-language-server/libexec/meta/3rd/OpenResty/library/ngx/balancer.lua

在 nvim-lspconfig: lua_ls 中有默认可用的配置，其中有配置项 Lua.workspace.library 是提供类型注释文件目录的，在 Using Definition Files 提到 LLS-Addons 提供了大量的常用库类型定义。

其项目的目录与 lua-language-server/libexec/meta/3rd 差不多，只是目录包含差太多了，就 ~/.local/share/nvim/mason/packages/lua-language-server/libexec/meta/3rd/OpenResty/library/ngx/balancer.lua 文件而言，其定义与当前 addons/openresty 子模块链接到的 openresty/library/ngx/balancer.lua 一致，但这个子模块已许久未更新，如 openresty/library/ngx/balancer.lua 明显与当前使用的不一样

这个文件是在 mason.nvim 导致的，开始只在其代码中发现 mason.nvim/lua/mason-core/installer/managers/common.lua 一点相关，但后面发现还有个 mason-registry 用于定义相关源如 mason-registry/packages/lua-language-server/package.yaml ，其中都是 libexec/bin/lua-language-server 相关，而 libexec/meta/3rd/OpenResty/library/ngx/balancer.lua 是由 lua-language-server/releases 中压缩包提供的，也在 lua-language-server/meta ，其中的 lua-language-server/meta/3rd/OpenResty 子模块链接到是未更新前的 LuaCATS/openresty ，这也就是为何 ngx.balancer 等类型定义几乎不可用的原因！

解决

在 lazyvim 中现在使用 lazydev.nvim: Faster LuaLS setup for Neovim 来配置 lua ls，参考 feature: load library on filename #39

---@type LazySpec[]
return {
  -- [feature: load library on filename #39](https://github.com/folke/lazydev.nvim/issues/39#issuecomment-2203460917)
  {
    "LuaCATS/openresty",
    name = "lua-openresty-types",
    lazy = true,
  },
  {
    "folke/lazydev.nvim",
    ---@module 'lazydev'
    ---@param opts lazydev.Config
    opts = function(_, opts)
      ---@type lazydev.Library.spec[]
      local libs = {
        "lua-openresty-types/library",
        -- { path = "luassert-types/library", words = { "assert" } },
        -- { path = "lua-openresty-types/library" },
      }
      vim.list_extend(opts.library, libs)
    end,
  },
}

注意：如果当前目录下存在 .luarc.json 可能会导致当前的配置无效 docs: hint how to deal with .luarc.json #64
