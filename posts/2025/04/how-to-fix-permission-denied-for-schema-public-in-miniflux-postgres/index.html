如何修复 Miniflux Postgres 中的 "Permission Denied for Schema Public" 问题

2025年4月2日10:10
阅读时长: 2 分钟

从 miniflux 2.2.6 升级到 2.2.7 时发现服务停止，查看 docker logs

1
2

time=2025-04-02T09:59:39.019+08:00 level=INFO msg="Running database migrations" current_version=104 latest_version=107 driver=postgresql
[Migration v106] pq: permission denied for schema public

注意：在目前最新版本 Miniflux 2.2.14 中移除了 HSTORE 扩展要求 Database Configuration ，不再需要 SUPERUSER 权限！查看相关 miniflux 历史文档 miniflux/website

notes

There is a SQL migration in Miniflux 2.2.14 to remove HSTORE extension from the database.

If you are seeing this Postgres error: Error: pq: must be owner of extension hstore, you can fix it by running the following SQL command as a superuser for the Miniflux database:

1

DROP EXTENSION hstore;

This error means you initially created the hstore extension as a different database user than the one you are currently using for Miniflux.

分析

在 创建 miniflux 数据库 发现需要在架构迁移时使用 HSTORE 扩展。 相关问题 Postgres 15. permission denied for schema public [closed]

Enabling HSTORE extension for PostgresqlCreating Postgresql extensions requires the `SUPERUSER` privilege. Several solutions are available:

  1. Give SUPERUSER privileges to the miniflux user only during the schema migration:

    1
2
3

    ALTER USER miniflux WITH SUPERUSER;
-- Run the migrations (miniflux -migrate)
ALTER USER miniflux WITH NOSUPERUSER;

  2. You could create the hstore extension with another user that have the SUPERUSER privileges before running the migrations.

    1
2

    sudo -u postgres psql $MINIFLUX_DATABASE
> CREATE EXTENSION hstore;

Note that if you use Debian or Ubuntu, you might have to install the postgresql-contrib package to activate the HSTORE extension.

Recent versions of Miniflux non longer uses the HSTORE extension but it still required to run the SQL migrations.

解决

在架构迁移期间向 miniflux 用户授予权限 SUPERUSER 即可

1
2
3

ALTER USER miniflux WITH SUPERUSER;
-- Run the migrations (miniflux -migrate)
ALTER USER miniflux WITH NOSUPERUSER;
