阅读时长: 4 分钟

参考 虚空终端 Docs：DNS 流程 中提供的流程解析，问题出现在这个 2 个 doh 连接时未被 rule 规则处理导致解析域名直连超时， 即使 rules 中包含 doh 域名走代理也无效。mihomo 提供了配置 respect-rules 允许 dns 连接遵守路由规则，参考 Feature 关于 DNS 的 respect-rule #1535

简单来说，rules 里面的规则不仅仅匹配域名，也匹配进程名、端口号等等，而且域名还有可能是 sniff 嗅探得到的， 但 DNS 模块却拿不到这么多的元数据，所以直接生搬硬套会产生很多很困惑的情况 （比如出现了 rules 根据端口号匹配到某个 proxy 出站，但是 nameserver-policy 却只能根据域名匹配到另一个 dns server）

respect-rule 只是让 dns 服务器本身的链接（即 1.1.1.1/8.8.8.8/223.5.5.5 这些链接）遵循 rules 出站， 而不是像原版 clash 那样粗暴的直连，也不用像之前版本那样用 #PROXY 那样的格式写死出口

让你在 nameserver-policy 中单独写一遍分流规则就是要让你清楚明白你自己在做什么 （即 nameserver-policy 和 rules 是不一样的，nameserver-policy 只能匹配域名规则， 而且这里的域名也是未经过嗅探直接由其他程序传过来的）

如果配置了 respect-rules 会在连接中显示 dns

在 虚空终端 Docs：DNS 指定 代理/接口 进行连接 中提到可使用 tls://dns.google#proxy 形式指定 dns 走代理，类似 respect-rules。下面是指定 https://dns.cloudflare.com/dns-query#PROXY 的部分日志

1
2

[info] [TCP] mihomo --> dns.cloudflare.com:443 doesn't match any rule using PRO 新加坡03 | 4x
[info] [UDP] mihomo --> dns.cloudflare.com:443 doesn't match any rule using PRO 新加坡03 | 4x

解决

最后使用 respect-rules: true 让 dns 走路由规则即可
