如何在 windows 上安装 nvim-treesitter

2025年9月18日14:04
阅读时长: 3 分钟

在最近的 lazyvim v15.0.0 更新中提到 migrate to nvim-treesitter main branch ，结果我直接使用 :Lazy 更新时发现无法安装，提示 cl.exe prog not found

分析

注意：在故障排除时未记录过程，下面的分析仅表示大致的处理方式

在 nvim 首次更新后启动时出现一大堆错误，解决完一些重命名插件的问题后发现 nvim-treesitter 总是更新失败， 其更新的通知超快且未被保存在通知历史中，无法直接查看日志，而且 LazyVim 的 cmdline 样式出错，只要输入 : 每输入 1 个字符就开始通知 error，不过可使用默认左下角的 cmdline 输入，尝试使用 :TSLog 查看日志。

还好能正常查看 TSLog，发现是 cl.exe prog not found 并伴随一堆 cl 编译参数。由于之前参考 nvim-treesitter/wiki/Windows support/zig 使用 zig 作为 c 编译器用于 treesitter 安装，并且在 Which C compiler will be used? 中默认有配置为

1

M.compilers = { vim.fn.getenv("CC"), "cc", "gcc", "clang", "cl", "zig" }

这里就很疑惑为何 cl 在 zig 前面，而 cl 不存在也不使用 zig。我尝试使用 $env:CC=zig 再次启动 nvim 后发现问题变成 zig 不是一个 c 编译器（出现 zig 命令的帮助输出表示使用了 zig 命令但未特殊处理如 zig cc 作为 c 编译器），这就很奇怪，明明支持 zig 的怎么出现问题？

我在 nvim-treesitter github 中怎么也找不到问题所在，且 README 中确实存在相关链接！但我是后知后觉，在检查过程中才发现当前 nvim-treesitter 默认展示的 master 分支已经 4 个月未有更新，且其首先就提示写明了使用新的 main 分支，也有和我一样的糊涂蛋： Unable to load parser on Windows 11 #8112

The master branch is frozen and provided for backward compatibility only. All future updates happen on the main branch , which will become the default branch in the future.

在 main 新分支中发现更新的安装要求，不仅需要 新的 c 编译器要求 ，还需要 tree-sitter-cli 和 Node 环境

  • Unix platforms require cc to be the C compiler. This can be found by installing cc/clang on Linux distributions and Xcode on macOS, for example.
  • Windows platforms targeting MSVC (e.g. your target name ends in -msvc) require Visual Studio to be installed. cc-rs attempts to locate it, and if it fails, cl.exe is expected to be available in PATH. This can be set up by running the appropriate developer tools shell.
  • Windows platforms targeting MinGW (e.g. your target name ends in -gnu) require cc to be available in PATH. We recommend the MinGW-w64 distribution. You may also acquire it via MSYS2 , as explained here . Make sure to install the appropriate architecture corresponding to your installation of rustc. GCC from older MinGW project is compatible only with 32-bit rust compiler.

对于 rust 开发者，在 windows 上安装时默认就是 MSVC 环境，我很疑惑为何未识别到 MSVC 环境。deepseek 给我的建议是：

cl.exe 的位置 不是固定 的，它取决于你的 Visual Studio 版本、安装路径以及选择的构建架构（x86, x64, ARM 等）。使用 Visual Studio 自带的开发者命令行（最简单、最推荐），这是微软官方推荐的方式，因为它会自动为你配置好所有正确的环境变量（包括 PATH, INCLUDE, LIB 等），完全无需手动查找。

解决

我在 windows terminal 中找到 Developer PowerShell for VS 2022 进入 powershell 后，运行 nvim 发现虽然 cl.exe 已找到，但又出现了一个新问题：fatal error cannot open include file: stdio.h no such file or directory 。我在搜索这个问题时突然想到是否是 windows SDK 未安装的问题（可能是在 google 时出现了 SDK 相关）！打开 Visual Studio Installer 安装：

重新进入 Developer PowerShell for VS 2022 运行 nvim 即可正常编译，部分功能安装失败可能需要反复进入 nvim 编译安装。

在安装了 SDK 后发现 nvim 不再需要进入 Developer PowerShell for VS 2022 也能识别 cl.exe MSVC 环境正常编译 treesitter 相关语言功能。

另外在 raspberry pi 4 上更新 gitcommit 时编译超长时间 14h 左右，尝试编译了 2 次都由于内存不足导致无法响应失败， 可能是由于 2G 内存不足 swap 导致的？最后是主动关闭了部分服务才勉强编译成功。
