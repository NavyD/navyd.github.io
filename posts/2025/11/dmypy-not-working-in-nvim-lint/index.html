在 nvim-lint 中的 dmypy 无法工作

2025年11月1日14:42
阅读时长: 2 分钟

在 neovim 中编辑 py 代码时 dmypy 只能偶尔提示诊断信息， 偶尔显示后编辑保存后又无法提示！

分析

首先尝试检查 dmypy 是否被 neovim 正常启动。

检查 nvim-lint

从 Add dmypy linter #707 添加了 dmypy，在 Feature: Please provide a LintInfo command #559 , How can I check if all linters for my file type works properly? #675 提到如何检查当前 buffer 活动的 linter 是不可能的，如 Get the current running linters for your buffer :

1

require("lint").get_running()

这个方法可能无效，虽然可能输出 { "markdownlint-cli2" } ，但 dmypy 这个是怎么也无法显示出来，但后台 daemon 进程是一直存在的，所以这个方法不可靠！

目前可以下面的代码查看当前 buffer 中启用的 linter :

1
2
3

require("lint").linters_by_ft[vim.bo.filetype]
  -- output:
-- { "mypy" }

在 Request to remove mypy hardcoded config - python_executable #742 , mypy does not work under a venv #662 提到需要移除 mypy 命令硬编码的参数 --python-executable ，而 lua/lint/linters/dmypy.lua 未移除命令参数 --python_executable ，尝试在 lazyvim 中覆盖重新配置 dmypy linter 参数：

  cmd = "dmypy",

但再次启动编辑 py 文件后还是 dmypy 存在类似的问题，而 mypy 一直都可以正常工作。

检查系统 dmypy 进程

从上面发现可能不是 nvim-lint 的问题，尝试看看系统中的 dmypy 进程是否正常启动。 使用 btop 发现在 neovim 启动后正常，在编辑保存后 dmypy 诊断信息无效，但 dmypy 进程还存在，退出 neovim 后 dmypy daemon 进程还存在，我还发现在终止 dmypy 进程后可以正常工作提供诊断信息，但后续编辑仍然会失败。

mason

还有一个问题，mypy 应该被安装在 venv 中而还是从 mason 等非当前项目的 venv 中启动，这可能会导致出现许多类型缺失问题。

总结

目前没有解决方法，只能使用 mypy 代替 dmypy，但这在大型项目中 lint 的速度可能会十分影响体验。
