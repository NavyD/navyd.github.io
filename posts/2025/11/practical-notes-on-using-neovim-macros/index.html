录制宏

下面是执行的宏：

1

vi(?\%V{.\{-}}^M^[^["yyi{]Aa, ^Ry^[[avi(?^P^M^[^[ca{%s^[[avi(?^P^M^[^[@a

注意：^M, ^[, ^P, ^R 分别表示 <CR> , <ESC> , <C-p> , <C-r>，参考 使用 ctrl-v 控制字符

具体操作是：

  1. 录制宏 qa 。
  2. 在 v 模式选中 log.info(f"xx") 中的参数 f"xx" 后退出 v 模式。如 vi(v 。
  3. 从上次选中的范围内 \%V 反向 ? 搜索 {.\{-}} 。
  4. 复制最后一个 {xx} 的内容 xx 到寄存器 y 中。
  5. 移动光标 ]A 到这个参数的后面并插入 , 与粘贴寄存器 y 的内容作为新的参数。
  6. 将光标移动 [a 回到这个新参数前（避免单个字符为参数时如 (f"", s) 与 (f"", args) 移动光标的区别）。
  7. 执行步骤 2,3 重新搜索 {xx} 的位置。
  8. 使用 %s 替换 {xx} : ca{%s 。
  9. 最后递归的调用宏 @a 直到搜索 {.\{-}} 失败。
  10. 退出录制宏 q 。

这个宏实际存在一些问题：

  • 需要先找到 log.info(f"") 语句搜索 /log\w*\.\w\+(\n*\s*f" 后再执行 @a ，由于 @a 中重新搜索了， 执行完后还需要再搜索 /log\w*\.\w\+(\n*\s*f" ，n/N 搜索上下一个会被 @a 中的搜索覆盖，非常不方便
  • @a 执行的比较慢，同时还存在边缘情况，可能会修改失败

再录制一个宏：

  1. 执行 qq 录制宏
  2. 搜索 /log\w*\.\w\+(\n*\s*f"
  3. 执行之前的宏 @a
  4. 退出录制宏 q

但这又引入一个问题，在搜索失败后会自动停止宏的执行，递归宏 @a 便是依赖这个机制退出的，但没想到的是 @a 的停止也会导致 @q 宏的执行。 又尝试先保存 last-pattern @/ ，然后 try-conditionals 捕获 @a 的搜索错误后恢复 @/ 即可！

1
2
3
4
5

:let last_pat = @/
:try
:exe 'norm! @a'
:endtry
:let @/ = last_pat

但在执行到 :exe 'norm! @a' 时出现在不停的修改一个个 {xx} 语句，吓的我赶紧停 ctrl+c , esc 不停的按，还好未保存，有几次的修改都是有 bug 的，记得一次后面的参数一堆 log.info(f"%s", arg, path, ..., path) ，给我整出阴影来了。。

这个原因可能是 try 让 @a 的执行不再被其中的搜索失败中止，或者是由于 vi(?\%V{.\{-}} 不停的向下搜索，而不是被限制在上次搜索范围内。说到底这个 \%V 有很大的不确定性，多次重复的搜索可能会导致上次范围修改的问题。

限制搜索范围

现在看来是这个宏 @a 的问题，依赖 \%V 这个上次的搜索范围不靠谱， 由于 {xx} 这种 log 语句存在多个，需要一种方法可以在指定范围内搜索， 参考 search-range 可以使用

  • /%>l : 在指定行范围内搜索如 /\%>199l\%<300llimit
  • :/range-pattern : 如 :.,/pattern 表示从当前行开始直到首个 pattern 的行
  • :substitute : 在指定行范围内替换如 :.,300s/Pattern//gc ，注意添加 c 选项开启在确认提示中使用 n 跳转下一个后使用 q 退出即可达到搜索跳转的效果

这里选择使用 \%>l 搜索方便，由于这个宏的操作比较复杂， 录制一个宏如果出错重置太麻烦，不如写一个 vim script 函数直观方便。

function! PyLogFstr2Args()
  try
    " 查找 log.info(f"xx") 的语句
    exe 'norm! /log\w*\.\w\+(\n*\s*f"' . "\<CR>"
  catch /.*/
    echo "未找到 log f-string 语句"
    return 0
  endtry

  " 找到参数位置，方便修改后回到起始
  norm! f(
  let start_pos = getpos('.')
  norm! %
  let end_pos = getpos('.')

  " 将 `{xx}` 替换为 `%s` 并添加参数 `xx`
  let count = 0
  try
    while 1
      let count += 1
      " 避免出错时无限循环导致修改操作崩溃
      if count > 10
        throw 'too many args error'
      endif

      " 在 log 语句行的范围内搜索 `{xx}`
      exe printf('norm! /\%%>%sl\%%<%sl{.\{-}}' . "\<CR>", start_pos[1] - 1, end_pos[1] + 1)

      " let choice = confirm("continue " . start_pos[1] . "-" . end_pos[1], "&Yes\n&No", 1, "Question")
      " if choice != 1
      "   break
      " endif

      " 复制到 reg y 中并替换为 `%s`
      exe 'norm! "yyi{ca{%s' . "\<ESC>"
      call setpos('.', start_pos)
      " 从在最后的 `)` 前插入 `, ` 并粘贴后移动到 `)` 上
      exe 'norm! %i, ' . "\<ESC>" . '"ypl'
      " 更新位置 不必要的操作
      " let end_pos = getpos('.')
    endwhile
  catch /^Vim\%((\a\+)\)\=:E486/
    echo '参数替换完成'
  endtry

  let count = 0
  call setpos('.', start_pos)
  try
    while 1
      let count += 1
      if count > 5
        throw 'too many args error'
      endif
      " 搜索 `f"`
      exe printf('norm! /\%%>%sl\%%<%sl\((\|\s\+\)\s*f"' . "\<CR>", start_pos[1] - 1, end_pos[1] + 1)
      " exe printf('norm! /\%%>%sl\%%<%slf"' . "\<CR>", start_pos[1] - 1, end_pos[1] + 1)
      " 删除 `f`
      norm! ffx
    endwhile
  catch /^Vim\%((\a\+)\)\=:E486/
    echo '删除f完成'
  endtry
endfunction

如何将宏转换为可打印字符

在 vim 中的宏存在特殊键如 esc 在 vim 中可使用 <C-v><Esc> 输入 esc 键作为特殊字符类似 ^[ ，但无法被其它程序读取打印，为了可读取性需要转换。

目前可使用 :echo 和 strtrans() 函数

1
2
3
4
5
6
7
8
9

" 将宏内容转换为可读字符串
:echo strtrans(@a)

" 或者使用 string() 函数
:echo string(@a)

" 或直接使用 echo
:echo @a
:echo 'test^['

注意：如果宏内容中包含 <CR> 会中断前后的内容，需要去除 <CR> 才能正常转换

调试命令说明

  • s (step) - 单步执行，进入函数
  • n (next) - 单步执行，不进入函数
  • c (continue) - 继续执行直到断点或结束
  • q (quit) - 退出调试
  • i (interrupt) - 中断执行
  • f (finish) - 执行直到当前函数结束

是否可将 catch /pattern/ 中的模式作为作为变量使用

在多个 catch 时通常有相同的模式，如果能作为同一个变量更方便维护，参考 Variable Interpolation in Vimscript catch clause 与 :catch 中的 pattern 必须是字面字符串，不能使用变量，但也有其它方案：

let target_error = 'E492'

try
    " 可能出错的代码
    NotAValidCommand
catch
    if v:exception =~ target_error
        echo "捕获到目标错误：" . v:exception
        " 处理特定错误
    else
        echo "其他错误：" . v:exception
        " 重新抛出或其他处理
    endif
endtry

注意：execute 'catch /' . error_pattern . '/' 这种亲测无效

如何编辑宏

通常录制宏的时候有错误或不必要的操作时需要修改，基本步骤：

  1. 录制宏到某个寄存器（比如 q）。
  2. 将宏寄存器的内容取出（如粘贴到当前光标位置）修改。
  3. 将修改后的内容放回寄存器。

问题是录制宏内有许多特殊字符如 ^[=<ESC>，修改其内容是一个不小的挑战。

另外也可以在命令行中使用 :let @q='...' 来定义宏，如

1
2
3
4
5
6
7

" 定义搜索宏
:let @q = "/TODO\<CR>dd"          " 搜索 TODO 并删除
:let @q = 'iText^['               " ^[ 是 Esc（按 Ctrl+V, Esc 输入）
" 引号包装文本
:let @q = "i\"\<Esc>ea\"\<Esc>"
" 带错误处理的递归宏
:let @r = ":try\<CR>/TODO\<CR>dd@r\<CR>:catch\<CR>:endtry\<CR>"
