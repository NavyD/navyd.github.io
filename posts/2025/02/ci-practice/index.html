并行

在 pre-commit 时通常会存在检查与修复操作，一个问题，并行处理同一个文件且都尝试更新时，如何处理竞争条件。

配置 parallel 可以让 commands Scripts jobs 类型的任务并行，但有时对其中某些特定的任务是需要先后顺序的，如所有的 lint 可以并行，但 fixed 通常需要在 lint 后执行避免竞争

run with shell

在运行命令 run: command list 时无法指定 shell，*nix, windows 不兼容语法，只能使用 scripts 文件执行，对于某些简单的命令非常不方便。

如检查文件名在 windows 上是否合法参考 # Add check for illegal Windows filenames 使用 (?i)((^|/)(CON|PRN|AUX|NUL|COM[\d¹²³]|LPT[\d¹²³])(\.|/|$)|[<>:\"\\|?*\x00-\x1F]|/[^/]*[\.\s]/|[^/]*[\.\s]$) 正则检查时需要创建文件而不能在 yaml 文件中写简单 python 的代码。

另外，在 run: command to {staged_files} 看起来也非常不稳定，使用 quotes 处理模板，可能存在转义的问题。如 run: yarn eslint "{staged_files}" 会被解析为 yarn eslint "file1.js" "file2.js" "[strange name].js"

尽管在 How to avoid git commit if one sub command in parallel a command fails #961 看到可以分离 shell 命令为多个 job 组合，但在 windows 上没有 shell 的功能是致命的，如使用环境变量等，总不能为了 2 行脚本写 1 个文件运行，总之这个跨平台基本是无法使用的，如果可以 设置默认 shell 和工作目录 就好了

为了兼容多平台可以使用 skip.run 运行命令检测当前是否为 windows

- name: lint lua on windows
  skip:
    - run: sh -c 'exit 0'
- name: lint lua on unix
  skip:
    - run: cmd.exe /c 'exit 0'

最后，我打开了一个 PR feat: Add shell options to run commands #965 添加 shell 选项类似 jobs.<job_id>.defaults.run.shell 在多个平台允许指定 shell 运行程序

注意：从 lefthook v1.11.5 开始在中在 windows 平台上使用 git-bash 执行命令修复了这个问题 fix: windows scripts issues #979
