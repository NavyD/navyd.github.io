hugo new content

在使用hugo new content posts/your-post.md创建一个 md 文件content/posts/your-post.md，但更好的博客目录结构可以使用posts/2025/01/your-post/index.md这种

根据 leaf-bundles 自动创建叶子结点目录结构，根据常用的 shell 使用下面的命令运行即可

1

hugo new posts/$(date +'%Y/%m')/'your post'

1

hugo new "posts/$(Get-Date -Format 'yyyy/MM')/my posts"

如何兼容多种主题

由于多种主题间的 params 是不兼容的，一旦在 md 的 front matter 中指定了主题的配置，会导致切换主题后无效。如果允许动态的修改 front matter 中的主题的配置，能轻易的兼容多种主题

模板

从模板中通过 Override the base template 和 Template lookup order 重置.Site.Params变量是不可行的，这是由于所有全局模板变量基本是只读的，无法更新，如果使用 hugo.Store 允许更新但无法覆盖 params api

在 Theme components 中提到允许指定theme = ['my-shortcodes', 'base-theme']覆盖主题，尽管也允许使用 Merge configuration from themes 参考示例 Allow smarter merging of config (esp. params) from themes #8633 合并主题配置，但有这样一种需求是无法满足的：当前 post 中如果存在 1 个图片链接则作为文章 cover

大多数主题都有 cover 图片配置参数，但这样的逻辑处理却需要动态处理，只能修改主题的处理逻辑。但如果可以在 build page 时修改 front matter 动态的设置 cover 就可以避免修改主题也能达成类似的效果

如何访问题部分中的 Config.toml 值

有一个简单的想法，在 Link render hooks 中检查当前启用的主题设置不同的 link 属性来兼容多种主题。

hugo 可以通过 Site.Config 获取部分配置信息 Privacy ，如果需要所有配置信息则需要主动读取配置文件 {{ $config := os.ReadFile "config.toml" | transform.Unmarshal }} 或在配置文件中添加需要的信息到 [params] 中使用 .Site.Params 获取，读取固定的配置文件由于 hugo 可随时指定配置文件路径导致其稳定性非常脆弱，使用 params 又会导致重复配置的问题

目前来看这不是一个着急的问题，毕竟主题不常换

Content adapters

根据 Content adapters 通过 go 模板content/$section/_content.gotmpl在构建时动态添加 page 生成静态页面

问题

_content.gotmpl模板只能在构建时使用，其相对于主题中能使用的众多模板 Methods 相当有限 content-adapters/#methods ，只要是与 Page 相关都不可用，如 Site.Config 。

想要动态生成元数据就需要解析 md 文件，但 hugo 目前不提供在构建阶段解析 markdown,html 的方法，如 transform.Markdownify 在这个阶段使用将会出现this method cannot be called before the site is fully initialized错误。

另外，如果只用 go 模板，一旦代码规模稍大其可维护性必然很糟糕。

在 github 上发现大部分都是使用解析一个 data.json 文件添加到 page，而不是复杂的解析 md 文件，问题就变成了解析 md 文件到 json 再使用_content.gotmpl解析添加到 page

由于 hugo 不支持调用外部命令运行 Configuration option to invoke a command upon build #9460 ，在hugo server|build等命令运行前需要处理好 data.json 避免部分数据更新无效的问题

部署 gh-pages

gh-pages 分支

在 gh-pages 分支中保留当前构建的 static 页面，默认情况下会保留 deploy 的提交，可能导致仓库大小激增。

在 actions-gh-pages #Force orphan force_orphan 中提到可以使用force_orphan: true仅保留最新提交

1
2
3
4
5
6

- name: Deploy
  uses: peaceiris/actions-gh-pages@v4
  with:
    github_token: ${{ secrets.GITHUB_TOKEN }}
    publish_dir: ./public
    force_orphan: true

兼容 wiki 链接

目前未找到兼容![[img]],[[post.md]]转换为标准 md 链接的方式，参考 Support wiki-style internal page links #3606 只能修改 obsidian 从默认 wiki 方式转为标准的 md 链接避免这个问题

虽然可以尝试使用 Content adapters 在模板中替换 [[link]] 作为标准的 [text](link) 链接即可，但由于 markdown 比较复杂，无法用简单的正则表达式正确地做到这一点，有许多边缘情况需要考虑，过于复杂的正则也可能导致文本匹配性能问题。

兼容 md 内部文件链接

对于如 content/posts/this is post/index.md 内部文件有链接如 [xxx](../other post/index.md) 应该被解析成 hugo page 链接如 [xxx](/posts/other-post) ，但由于正则的复杂性，不应该使用正则替换。

Link render hooks

在 Link render hooks 提到可以使用 layouts/_default/_markup/render-link.html 覆盖主题配置和 embedded link render hook 。

添加 HTML 文件作为资源

有时需要添加如 html, md, txt 等文件到文章作为链接资源，但 hugo 对于 Content management Page resources 特殊内容资源文件如 html, md 等视为 page 类型，在 leaf bundles 中的这些文件默认不会加载作为资源文件到 public 目录中。

参考 Add a way to identify a non-Page HTML etc. resource #12274 需要主动将这种类型的文件发布：

1
2
3

{{ ((.Resources.Get "a.html").Content | resources.FromString "/p1/a.html").RelPermalink }}
{{ ((.Resources.Get "b.html").Content | resources.FromString "/p1/b.html").Permalink }}
{{ ((.Resources.Get "c.html").Content | resources.FromString "/p1/c.html").Publish }}

注意：由于 page 类型的链接使用的文件名可能会由于 logical path 的转换与原始的文件名不同，如 fuck post.md 作为 page 时的路径名为 fuck-post.md，从而导致匹配文件名失败，可以使用 .Page.Resources.ByType 获取当前目录下的所有 page 类型的资源

        但对于这样的page资源会事先被`.Page.GetPage path`获取，所以无需处理
    */}}

扩展语法

转义 hugo shortcode

在 markdown 源码中使用 <!-- {{% --> 与 <!-- %}} --> 可以让这之中的代码转义为原始代码避免被渲染，同时在 md 文档中隐藏 {{% 。

参考：

  • Can I escape a shortcode from a Hugo theme from blogdown

可折叠内容

在 GitHub 上写入/使用高级格式/ 使用折叠部分组织信息 中可以使用 <details> 将内容折叠，直到单击展开详细信息，但在 hugo 中默认不会渲染 html，但可以在 configuration-markup/#rendererunsafe 使用 markup.goldmark.renderer.unsafe=true 渲染。

另外也可以使用 Shortcodes/Details 如

1
2
3

{{< details summary="See the details" >}}
This is a **bold** word.
{{< /details >}}
