我现在很慌，要是备份的数据出问题了那可就完蛋了！启动 pgadmin4 连接数据库发现只是部分表的数据没有了，最重要的 entries 表数据还存在，但也不确定是否完整。

我怀疑可能是从 postgresql 15 pg_dumpall 的数据在恢复到 postgresql 18 时出现问题，尝试使用 docker 容器恢复到 postgresql 15 版本看看数据是否有问题。

由于当前的 pg_dumpall 备份的文件包含 immich 数据库，其中有使用 tensorchord/VectorChord ，参考 installation/docker/VectorChord Image 使用 tensorchord/vchord-postgres docker 镜像，考虑到 immich/Pre-existing Postgres/Prerequisites 当前 immich 支持其版本范围：

Immich is known to work with Postgres versions >= 14, < 19.

VectorChord is known to work with pgvector versions >= 0.7, < 0.9.

The Immich server will check the VectorChord version on startup to ensure compatibility, and refuse to start if a compatible version is not found. The current accepted range for VectorChord is >= 0.3, < 0.6.

重建 miniflux 数据库

对于 debian 上的 postgresql 18 实例已经恢复了最新的备份，也就是 miniflux 数据库需要重新恢复到 2025-10-31 04:44:11 ，而其它数据库如 immich 则应该保持最新。由于 pg_dumpall 备份文件不支持恢复特定数据库，所以需要恢复所有数据后再备份单个数据库 miniflux ，然后在原 postgresql 18 实例中重建 miniflux 数据库并导入这个新备份的数据

1
2

# pg 现在是 18 版本
docker exec -it pg pg_dump -U postgres miniflux >miniflux.bak.sql

创建新 miniflux 数据库参考 Database Creation ：

1
2
3

createdb miniflux2
createuser -P miniflux
createdb -O miniflux miniflux2

使用在 psql 中执行而不使用 postgresql 提供的 shell 命令创建更清楚方便，注意这里只删除了 miniflux 数据库，而不需要重新创建用户 miniflux 直接使用即可

1
2
3
4
5
6

-- 终止当前 miniflux 数据库所有的连接
SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = 'miniflux' AND pid <> pg_backend_pid();
-- 删除 miniflux 数据库
DROP DATABASE miniflux;
-- 创建新数据库并指定用户
CREATE DATABASE miniflux OWNER miniflux;

恢复数据：

1

psql -U postgres -d miniflux -f miniflux.bak.sql

重新从 docker postgresql 18 容器中备份再恢复启动 miniflux 2.2.14 可正常工作

总结

对于重要的数据备份还是需要经常测试的否则出现问题就严重了。
