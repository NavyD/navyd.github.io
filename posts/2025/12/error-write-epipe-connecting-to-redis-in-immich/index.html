分析

原来在 debian 12 中安装的 redis 只需 bind 0.0.0.0 后 不需要额外配置即可正常连接，我尝试在局域网中连接 redis 发现无法连接，但本机可正常连接。

一顿搜索但未找到什么方法，由于这是新恢复的 postgresql 数据库为避免可能是 immich 内的问题，只得尝试使用 immich/docker-compose.yml 中提供的 redis 服务：

services:
  redis:
    container_name: immich_redis
    image: docker.io/valkey/valkey:8@sha256:81db6d39e1bba3b3ff32bd3a1b19a6d69690f94a3954ec131277b9a26b95b3aa
    healthcheck:
      test: redis-cli ping || exit 1
    restart: always

重新配置启动 immich 服务后可正常工作，这表示就是 redis 连接问题导致的。

我只能查看 /etc/redis/redis.conf 配置，幸好就在 bind 127.0.0.1 -::1 下方存在 protected-mode yes 配置项：

# ...
bind 127.0.0.1 -::1

# ...
# Protected mode is a layer of security protection, in order to avoid that
# Redis instances left open on the internet are accessed and exploited.
#
# When protected mode is on and the default user has no password, the server
# only accepts local connections from the IPv4 address (127.0.0.1), IPv6 address
# (::1) or Unix domain sockets.
#
# By default protected mode is enabled. You should disable it only if
# you are sure you want clients from other hosts to connect to Redis
# even if no authentication is configured.
protected-mode yes

解决

修改为 protected-mode no 后重启 redis 服务后可正常工作。

我查看备份 debian 12 中的 /etc/redis/redis.conf 中的配置是 protected-mode no 这也就是为何之前不存在这个问题的原因！

注意 bind 0.0.0.0 与 protected-mode no 允许无密码任何连接，要避免公网使用。

另外我发现从 immich v1.132.0 开始默认使用 valkey :

We are now using Valkey’s image for the Redis service in the default docker-compose.yml template. This is not a required change. If you wish to use it, you can download the docker-compose.yml file at the bottom of the release notes and replace the redis image with the new one.

尽管 redis 存在 license 反复变更的问题 Redis is now available under the AGPLv3 open source license ， 考虑到软件兼容性，切换到 valkey 还未到时候，目前 redis 可正常使用也不必更换，特别是对于个人用户使用场景而言。 参考 Redis is now available under the the OSI-approved AGPLv3 open source license
